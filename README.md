# DECORA V6.5

Work Particulars editor cards now have numbered headers, header-level remove controls, compact responsive fields, and a consistent red outlined remove action for subtotal/total and other removable layout rows. Existing calculations, printed invoice renderer, templates and backup formats are unchanged.

# DECORA V6.2

Builds on V6.1. Custom template designer now offers draggable business address, terms paragraph, logo, business name, invoice title, signature and custom text/paragraph blocks; selection resize handles and properties for custom text width, font size and alignment. Load Sample, Load Long Sample and Reference Layout have new consistent action cards with their original event IDs and handlers preserved. Classic remains the default and unmodified.

Note: invoice title remains a protected label; financial totals and work-item data remain generated by the existing engine. Resizing text may overlap adjacent content; check A4 and multi-page exports before using a custom layout. Browser interaction/export regression testing remains necessary.


## V6.3 UI consistency changes
- Screen-only preview header and toolbar refinements, including responsive pagination/zoom controls. The invoice paper renderer, pagination logic, and print/export CSS are unchanged.
- Standardized 44×44 work-item and advance-payment remove controls with accessible names. Original deletion callbacks unchanged.
- Styled native logo and signature file inputs in Settings with consistent picker button sizes and format hints. Existing input IDs and file handlers unchanged.
- Updated offline service worker cache and asset query versions to 6.3.
- Browser/device testing (especially multi-page PDF and mobile touch) remains recommended before production deployment.


## V6.4 — Invoice Edit advance-payment card refinement
- Advance payments now appear in individual numbered cards, with the existing remove action moved to each card header instead of beside the Date input.
- Payment Label and Amount share an aligned two-column grid; Date spans full width. On very narrow screens the two fields stack.
- Preserves the same field bindings, payment deletion callback, recalculation, invoice layout, stored data, template designer, Classic invoice, and exports.
- Screen-only CSS scoped to #advances; no invoice paper or print styles changed.
- Automated syntax/archive checks performed; browser/mobile regression testing still required.
